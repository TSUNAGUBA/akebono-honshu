## 0. この文書のスコープと既存設計との関係

既存 MVP（`product-master-to-purchase-order-flow.md`）は **「商品マスタ登録 → 完成品の発注書（製品発注）→ Excel出力」** を扱う。本文書はその **上流の生産軸** ＝ **「商品マスタ(BOM) → 生産指示書 → 素材発注書 → 未/済可視化」** を扱う。

```
                         ┌─────────────────────────────────────────────┐
                         │  商品マスタ（品番）+ BOM（素材構成・所要量）  │ ← 既存 product_families を BOM 拡張
                         └───────────────┬─────────────────────────────┘
                                         │ ＋ 生産数量を指定
              ┌──────────────────────────┼──────────────────────────┐
              ▼                                                      ▼
   ┌────────────────────┐                              ┌────────────────────────┐
   │ ② 生産指示書         │   BOM × 生産数量で所要量展開  │ ③ 素材の発注書           │
   │  （加工指図書）      │ ───────────────────────────► │  （生地材料発注）        │
   │  → 加工先（工場）へ  │                              │  → 素材仕入先へ          │
   └────────────────────┘                              └────────────────────────┘
              │                                                      │
              └───────────────► ④ 品番ごと「未/済」2軸バッジ ◄────────┘
                                （生産指示 未/済・素材発注 未/済）

   〔既存・別系統〕 完成品の製品発注書（purchase_orders）→ 工場から完成品を調達
```

> **重要（用語対応、提案書 p-31/p-32/p-15 で確定）:**
>
> | 本案件（依頼者）の用語 | 提案書 Apparel-ZONE の対応概念 | 本設計での実装名 |
> |---|---|---|
> | 商品マスタ＋生産に必要な素材 | 製品原価明細登録「1製品を作るのに必要な生地・付属を登録」 | `product_families` ＋ **`product_materials`（BOM）** |
> | 生産指示書 | **加工指図書**（企画情報を元に加工先へ発行） | **`production_instructions`** |
> | 素材の発注書 | **生地材料発注入力／生地材料発注確認書**（製品発注とは別系統） | **`material_orders`** |
> | 未/済ステータス | **指図残／工程実績／受注進捗状況照会** | 品番ごと2軸バッジ（派生算出） |
> | （既存）完成品の発注書 | **製品発注入力／ORDER SHEET** | `purchase_orders`（既存・変更しない） |

## 1. AS-IS（現行システムの事実）

### 1.1 現行5システムと二重入力（提案書 p-11/p-20）

| 現行システム | 主機能 | 生産軸での役割 |
|---|---|---|
| 生産管理システム（SQL Server 2017 `ProductControl`、約308MB） | 品番台帳・発注管理 | 品番台帳（企画/原価/素材）を保持。工場へ完成品を発注 |
| 販売管理「アラジン」 | 品番・発注・入荷・仕入・在庫・売上・債権債務 | 発注→入荷予定→仕入の3段消込。完成品の発注残管理 |
| 伝票発行「伝発名人」 | 伝票発行 | （対象外） |
| 会計「勘定奉行クラウド」 | 会計 | 連携のみ（リプレース対象外、製品/原材料/仕掛品勘定あり） |
| EDI「EOS名人」 | EDI・出荷 | 得意先商品変換マスタ |

> **真の課題（提案書 p-20 明記）:** 「現状、商品情報や発注の同じ情報を販売・生産システムそれぞれに入力している」。品番台帳が生産管理とアラジンに**189列で二重保持**されている。

### 1.2 現行の「発注」は完成品の発注（素材発注ではない）

生産管理の発注CSV（46列・2275行）／アラジンの発注書（ORDER SHEET）はいずれも **完成品(品番)を海外工場へ発注** するデータ。
- 仕入先＝中国南通・カンボジア・ミャンマー等のOEM工場、通貨 CNY/US
- 明細＝商品コード(品番) × カラー × サイズ、発注数量・発注単価
- ORDER SHEET の連絡欄「値札・証紙等の副資材は発注数×5%にて発注」＝**副資材はホンシュが別途手配**する運用が存在

### 1.3 素材情報の在り処（BOM の前提）

| 保持場所 | 形式 | 所要量 |
|---|---|---|
| 生産管理 品番台帳（189列） | **甲表素材・中板素材・底素材の3部位固定**（各1コード+名称） | ❌ なし（コードのみ） |
| アラジン 商品台帳（189列） | 同上（甲表/中板/底の3部位） | ❌ なし |
| アラジン SKUマスタ（138列）／販管連携 | **部位×素材×混率（1〜10枠）** | ❌ 枠はあるが全行空 |

> **設計上の最重要事実:** 現行は **素材を「コードのみ」で保持し、1足あたりの所要量（必要数）を一切持たない**。素材発注（数量算出）には所要量が不可欠なため、**BOM（素材構成＋所要量）は新規にデータ設計が必要**。

### 1.4 生産指示・工程・素材発注・未済は現行に専用データなし

- 発注CSV(46列)に **発注残・入荷済/未済・進捗ステータス列が存在しない**
- 生産指示書・工程実績・素材手配(所要量展開)に該当する帳票・データが**全資料に存在しない**
- アラジンは完成品については `完了区(0:未完/1:完了)` ＋ `発注残数量＝発注数−仕入数` を持つ（**未済管理の良い手本**）が、素材・生産指示には及ばない
- 現状は発注↔入荷を「商品コード・相手先NO(Sxxxx)・伝票備考(NN-NNNNN)」で**人手突合**して未済把握している推測

→ **結論:** 「素材発注・生産指示・未/済」は現行に手本のない**新規業務（空白領域）**。本SaaSで OEM 生産の実態に即して新規設計する。

## 2. To-Be（提案書 Apparel-ZONE が描く生産業務、p-31/p-32/p-15）

> 提案書では生産系は【オプション機能】【将来構想】扱い。本SaaSはこれを「直近3機能」として先行実装する。

### 2.1 企画・生産のシステム化（p-31）
- 「**1つの製品を作り上げるのに必要な生地、付属等の情報を登録**」＝ **BOM（部品構成）** の登録
- 企画段階で製品原価を試算、企画書を発行

### 2.2 加工指図と進捗管理（p-32）
- 「**企画情報を元に加工指図書を発行**」＝ 商品マスタを起点に生産指示書を作成
- 「**工場に指図後、各工程の実績を入力する事で工程の進捗状況や指図残を管理**」＝ 未/済（指図残）管理
- 「**加工先別と品番別** それぞれの角度で確認」＝ 品番ごと進捗の可視化（本案件の「品番ごと未/済」と整合）

### 2.3 発注の2系統（p-15 オプション機能）
- **製品発注入力／製品発注確認書**（＝既存 `purchase_orders`、完成品調達）
- **生地材料発注入力／生地材料発注確認書**（＝新規 `material_orders`、素材調達）
→ 提案書も製品発注と生地材料発注を **別系統** で持つ。素材発注は独立エンティティが妥当。

## 3. 本案件で確定した業務モデル（オペレーター承認 2026-06-22）

4つの設計判断をオペレーターが確定（推奨案採択）。

| # | 論点 | 確定 |
|---|---|---|
| 1 | 生産指示書・素材発注書の起点 | **商品マスタ(品番)＋生産数量**。品番を選び生産数量を指定→生産指示書を作成、その所要素材を素材発注書として出力 |
| 2 | 素材発注の数量算出 | **BOMを商品マスタに登録**。1足あたりの各素材所要量（甲皮/中底/底＋付属/副資材）を登録し、生産数量×所要量で自動算出 |
| 3 | 未/済の単位 | **品番ごと2軸バッジ**。品番ごとに「素材発注 未/済」「生産指示 未/済」を一覧表示。発行で「済」 |
| 4 | スコープ外要素の深さ | **ロードマップ＋データモデル骨格＋段階移行計画**まで（実装は直近3機能、拡張余地確保） |

### 3.1 直近スコープの業務フロー（詳細設計対象）

```
[1] 商品マスタ登録（既存）＋ BOM 登録（新規）
     品番（甲皮/中底/底素材＝既存）に加え、素材構成（部位・素材・所要量・単位・推奨仕入先）を登録
        例: 甲皮 ポリエステル 0.30 ㎡/足 / 中底 EVA 0.02 組/足 / 底 PVC 1.0 組/足 /
            付属 面ファスナー 1 組/足 / 副資材 値札 1 枚/足 …
        ↓
[2] 生産指示書（加工指図書）作成
     品番を選択 → 加工先（工場）・生産数量（色×サイズ別内訳）・希望納期を指定 → 発行
        → 生産指示書 Excel 出力（加工先へ送付）
        → この品番の「生産指示」ステータスが 済 に
        ↓
[3] 素材の発注書（生地材料発注）作成
     生産指示を起点に BOM×生産数量 で所要量を自動展開
        → 素材仕入先ごとに発注書を作成（所要量はプリセット、調整可）
        → 素材発注書 Excel 出力（素材仕入先へ送付）
        → この品番の「素材発注」ステータスが 済 に
        ↓
[4] 商品一覧で品番ごとに「素材発注 未/済」「生産指示 未/済」をバッジ可視化
     未着手の品番が一目で分かり、手配漏れを防ぐ
```

### 3.2 数量・単位の考え方
- **生産数量** は色×サイズ別に内訳を持つ（既存の色×サイズマトリクスUIを踏襲）。合計＝総生産足数。
- **所要量** は「1足あたりの数量＋単位」（例: 0.30 ㎡、1 組、1 枚）。
- **素材発注数量（推奨）** ＝ Σ(所要量 × 各SKU生産数量)。実発注は端数・ロット・ロス率を考慮し担当者が調整可（手入力上書き可）。
- **ロス率は BOM 行の任意フィールド**（`product_materials.loss_rate`、DEFAULT 0）。MVP の推奨数量は `所要量×数量` を基本とし、**ロス率を設定した行のみ** `×(1+loss_rate)` を加味する。実値・丸めルールは要ヒアリング（§7-3）。

## 4. データモデルの骨格（Phase 5 data-design-production.md へ申し送り）

```
既存（変更しない）                        新規（本案件）
─────────────────────                  ──────────────────────────────────────
product_families (品番企画)  ──1:N──►  product_materials  (BOM: 部位×素材×所要量×単位×推奨仕入先)
  ├ upper/insole/outsole_material_id              │
  │  （3部位の代表素材、表示用に存置）            │ 素材は materials マスタを参照
  └ products (SKU 色×サイズ)                      │ 仕入先は suppliers マスタを参照
                                                   ▼
product_families ──1:N──► production_instructions (生産指示書ヘッダ)
                            ├ factory_supplier_id（加工先）
                            ├ planned_quantity / due_date / status / instruction_no
                            └ production_instruction_lines (色×サイズ別 生産数量)

production_instructions ──1:N──► material_orders (素材発注書ヘッダ、素材仕入先別)
                                   ├ material_supplier_id
                                   ├ order_no / due_date / status
                                   └ material_order_lines (素材×所要量展開数量×単価)

品番ごと「未/済」バッジ = production_instructions / material_orders の存在・状態から派生算出
（denormalized cache は将来最適化、MVPは EXISTS サブクエリ＋インデックスで算出）
```

## 5. 既存マスタ・仕入先の扱い

| 論点 | 方針 |
|---|---|
| 加工先（工場） | 既存 `suppliers`（工場兼用、`item_conversion_code`＝品番7桁目）をそのまま使用 |
| 素材仕入先 | 既存 `suppliers` を使用。製品仕入先/素材仕入先の明示区分は現行に無く（`仕入先分類1-3`の値意味は要ヒアリング §7）、当面は区分せず選択可。将来 `suppliers` に区分追加余地 |
| 素材（付属・副資材含む） | 既存 `materials` マスタを使用。付属（面ファスナー・中敷等）・副資材（値札・証紙・箱）も `materials` に登録。必要なら `material_classifications` に分類追加 |
| 単位 | 当面は列挙（足/組/枚/個/m/㎡/cm/本）。将来 単位マスタ化の余地 |

## 6. スコープ外要素のロードマップ位置づけ（骨格設計）

提案書のモジュール（p-09）と現行アラジンの実機能を、本SaaSの段階導入ロードマップに対応づける。詳細は `architecture-production.md` §ロードマップ。

| 段階 | 領域 | 現行の手本 | 本案件での扱い |
|---|---|---|---|
| 実装済 | 商品マスタ・完成品発注書 | 品番台帳・ORDER SHEET | 既存 MVP |
| **今回詳細** | **BOM・生産指示・素材発注・未/済** | 提案書 p-31/32（空白領域） | **詳細設計＋実装対象** |
| 次 | 工程実績（加工先別/品番別 進捗） | 提案書 工程実績照会 | 骨格（生産指示の状態を多工程へ拡張） |
| 次 | 仕入/購買（発注→入荷予定→仕入 3段消込） | アラジン発注明細・入荷予定・仕入 | 骨格（完成品発注・素材発注の入荷消込） |
| 次 | 在庫（SKU×倉庫×月次、12倉庫） | アラジン在庫CSV・生産管理在庫帳票 | 骨格 |
| 後 | 受注・配分・出荷指図・ピッキング | 提案書受注管理・アラジン売上 | 骨格 |
| 後 | 売上・債権債務・与信 | アラジン売上明細・元帳・与信残高 | 骨格 |
| 後 | EDI連携（取引先商品変換）・会計連携 | EOS名人・商品変換マスタ・勘定奉行 | 骨格 |
