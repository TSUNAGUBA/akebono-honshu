# 旧システム項目 ↔ 現画面 項目パリティ分析（/refference 突合）

> **目的:** `/refference` 配下の旧システム（アラジン販売管理 + 生産管理システム）のデータ項目設計と、現行 Akebono Honshu の各画面項目を突合し、「欠落している項目」を可視化する。本書は項目追加の段階導入（フェーズ）計画の SoT となる。
>
> **背景:** ユーザー要望「現在の画面では多くが欠け落ちているように見える。それぞれのシーンにおける項目を完全一致させてほしい」への回答。旧システムの品番台帳は最大 189 列に及ぶため、全列の一括導入はスキーマ破壊リスクが高い。本書で全項目を棚卸しし、価値・リスクで段階導入する。

## 2. 本イテレーションで実施した変更

1. **選択コントロールの全オートコンプリート化（要望#4 完了）**
   - マスタ参照の全 `<select>` を部分一致オートコンプリート（`AutoComplete.vue` / 数値ID用 `MasterSelect.vue`）へ置換。
   - 対象: 商品新規/詳細、発注新規、生産指示新規、素材発注新規、BOM編集。固定列挙（年式/通貨/状態/部位/単位/編集理由）も同一UIに統一。
   - `pages/` 配下に素の `<select>` は0件（全置換を grep で確認）。
2. **欠落項目の表面化（要望#3 の一部）**
   - 発注: 副担当者1〜6（DTO実装済・UI未表示だった6枠を追加）。
   - 商品: 仕入単価の **為替レート**（外貨時）を入力UI＋一覧表示＋読取DTO(`CurrentSupplierPrice.ExchangeRate`)まで end-to-end で追加。
3. **データ構造の独立性・snapshot-copy の確認（要望#1,#2 完了）**
   - 商品/発注/生産は独立したテーブル・名前空間・サービスで実装済み。
   - 発注/生産の明細は作成時に商品から `sku/product_name/unit_price/currency` を **コピー（snapshot）** することを実装で確認（`PurchaseOrderService` line 68-74 他）。

## 3. 残項目の段階導入（フェーズ）提案

| フェーズ | 対象 | 内容 | リスク |
|---------|------|------|--------|
| Phase A | 商品: 小売価格/納品価格/管理季節/関税率/仕入区分 | 完成品の価格・通関の基本属性。`product_families` へ列追加＋migration＋DTO＋UI | 低（属性列追加のみ。SKU生成に影響なし） |
| Phase B | 発注: 相手先NO/取引区分/注文NO/備考拡張、明細ロットNO/CT数/入数 | 取引先発番と荷姿。海外発注書帳票の充実と整合 | 中（発注ヘッダ/明細スキーマ拡張） |
| Phase C | 商品: ドレー代/ブランド費/ロス/企画費/版権/入数/生地番号 | 原価パラメータ群。原価計算ロジックと合わせて設計 | 中 |
| Phase D | 取引先別商品変換、海外発注書の通関・出荷地欄 | 出荷・海外発注の本格対応。新マスタ要 | 中〜高 |
| 対象外 | 見積プロセス（仮番/見積単価/利益率）、アソート/セット、付箋、販管区分15種 | 既存設計で MVP除外。連携要件が固まり次第 | — |

> **注意:** Phase A〜D は既存データへの影響を評価し、列追加は NULL許容＋デフォルトで後方互換を保つ。各フェーズ着手前に対象列を確定し、CLAUDE.md「新規方針追加時の自己整合性 grep 手順」に従って受け入れ基準・データフローへの波及を反映する。
