## 2. データフロー（MVP）

```
┌────────────────┐
│ 取引先 Excel    │ (システム外、人手で参照)
└────────┬───────┘
         │ 手作業転記
         ▼
┌─────────────────────────────────────────┐
│ 商品マスタ (新システム)                    │
│   product_family (企画親)                 │
│     └─ product (11桁 SKU, 色×サイズ分)    │
│           └─ product_supplier_price       │
└──────────────┬──────────────────────────┘
               │ 連続フロー（UC-1）
               │ or 既存品番選択（UC-2）
               ▼
┌─────────────────────────────────────────┐
│ 発注書 (新システム)                        │
│   purchase_order (1依頼=1発注書)          │
│     ├─ purchase_order_line (品番×数量)   │
│     └─ purchase_order_text (連絡文章)    │
└──────────────┬──────────────────────────┘
               │ 出力
               ▼
┌─────────────────────────────────────────┐
│ 発注書 Excel ファイル (テンプレート流し込み) │
└──────────────┬──────────────────────────┘
               │ メール添付・FAX 等（システム外）
               ▼
┌────────────────┐
│ 工場/仕入先     │
└────────────────┘
```

**重要:** MVP は **生産管理 ↔ 受発注 の核心部分** を1つのシステム内で完結させる。販売管理側（受注・売上・出荷等）への連携は MVP 対象外。

---

## 3. システム化 vs システム外の俯瞰

### システム化対象（MVP 必須）

| カテゴリ | 内容 |
|---------|------|
| マスタ管理 | 18マスタ（既存17 + ユーザ）の CRUD、論理削除、コード重複・FK チェック。工場は `supplier` を兼用、甲皮素材は `material` を参照（追加マスタは作らない） |
| 商品マスタ登録 | 2層構造、サイズ展開、マルチ仕入先単価 |
| 発注書作成 | 国内画面相当、明細自動転記、連絡文章テンプレート |
| 発注書出力 | Excel 生成、発注番号採番 |
| 検索・参照 | 品番検索、発注書検索、履歴照会 |
| 改訂 | 枝番採番、発注中止フラグ |
| 認証 | ログイン、権限分離（要確認） |
| 監査ログ | 誰がいつ何を変更したか（仮説要件） |

### システム外（人手対応）

| カテゴリ | 内容 |
|---------|------|
| 取引先 Excel の解釈 | 依頼内容を人間が読んで判断（OCR・自動取り込みは将来課題） |
| 工場への発注書送付 | メール添付・FAX 送付（MVP 内では送信機能を持たない） |
| マスタ追加の妥当性判断 | 「この商品タイプを追加すべきか」等の意思決定 |
| 受領確認 | 工場からの受領返信は人間が確認 |

### MVP 範囲外（将来拡張）

| カテゴリ | 内容 |
|---------|------|
| 海外発注フロー | 4ロール（発注先・荷揚地・得意先・納品先）、複数倉庫、週次出荷スケジュール |
| 取引先 Excel 自動取込 | パーサ・OCR 等 |
| PDF 出力 | 現状 Excel のみ、PDF は将来 |
| 販売管理連携 | 受注・売上・出荷との統合 |
| 在庫管理 | 在庫トラッキング |
| 集計・分析 | ダッシュボード、レポート |
| 承認ワークフロー | スポンサーが「承認なし」と回答済み、必要になったら追加 |
