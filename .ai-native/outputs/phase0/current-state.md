## 1. 顧客の業界・事業内容

### 業界
**フットウェア（靴・スリッパ）+ ホームウェア（マット・クッション・卓上小物 等）の卸事業**

### 事業内容
- **業態:** B2B OEM/ODM（取引先からの個別依頼に基づき商品を企画・発注・卸す）
- **取引先:** しまむら、KEYUCA、AEON 等の小売チェーン / 流通センター
- **生産:** 海外工場（中国・カンボジア・ミャンマー等）と国内協力工場の両方を活用
- **商品アイデンティティ:** 11桁の品番（SKU）コード体系で全商品を管理

### 業界特性（既存システム由来）
- 品番は **マスタ選択 → 機械的に連結** して生成（年式+型式+季節+連番+工場+色+サイズ）
- マスタは論理削除原則（過去取引データの整合性保護）
- 季節商品とは独立に、定番（N始まり）商品も並行運用
- 多通貨（CNY/USD）原価管理が必要（中国外注品）

## 2. 現状の業務フロー（AS-IS）

### MVP 対象範囲（3ステージ・国内のみ）

```
[取引先]                              [生産管理部/課]                     [工場/仕入先]
    │ Excel/CSV 仕様                       │
    ├────────────────────────►   ① 商品マスタ登録 ─┐
                                          │      │ ほぼ同時実行
                                          │      │
                                          │   ② 発注書作成 ─┘
                                          │      │
                                          │   ③ 発注書出力 (Excel)
                                          │      │
                                          └──────────────────────────►
```

### 各ステージの特性

| 項目 | ①商品マスタ登録 | ②発注書作成 | ③発注書出力 |
|------|---------------|------------|------------|
| トリガー | 取引先からの個別依頼 | ①と同時 | ②の続き |
| アクター | 生産管理部/課 | 同左 | 同左 |
| 粒度 | 1企画 = 1セッション（色×サイズ一括展開） | 1依頼 = 1発注書 | 1発注書 = 1出力 |
| 入力 | Excel/CSV（手作業転記） | 商品マスタ + 都度入力 | 発注書 + テンプレート |
| 出力形式 | DBレコード | DBレコード | Excel |
| 承認 | 不明（要実ユーザ確認） | なし | なし |
| 改訂 | - | - | 発注番号に枝番付与 |

### 業務フローの構造的特性

- **MTO（Make-to-Order）パススルー:** 数量・納期は取引先依頼をそのまま転記
- **マルチ仕入先:** 1品番に対し複数仕入先・複数単価を保持
- **2層商品モデル:** 企画親 + 11桁 SKU 子（色×サイズ分）
- **取引先非依存カタログ:** 商品マスタは取引先と紐付かず再利用可能

### MVP 対象外（業務全体の一部のみが MVP）

見積、受注、出荷、在庫、売上集計、海外発注フロー、その他複数ステージ。
スポンサー発言: 「3ステージ以外もありますが、一旦はこの3ステージで進めることは可能ですか？」

詳細: `domain-context/business-flow/product-master-to-purchase-order-flow.md`

## 3. 理想の姿（仮説状態）

### 設計哲学（仮説）

**「速度・自動化」より「正しさ・誤入力防止」を優先**

#### 具体的方向性
- バリデーション中心の UX（入力時即時チェック、確認サマリ）
- 間違えにくい入力導線（プルダウン中心、必須項目視認性、誤組み合わせ拒否）
- 重複・矛盾の自動検知（品番衝突、色×サイズ整合性、価格未入力）
- 証跡・トレーサビリティ（誰が何をいつ入力・変更したか）

### 重要な留保

> **スポンサー発言:** 「現状発生しているとは聞いていません。ただあると良いと私が勝手に思っただけです。」

→ **「誤入力防止」は依頼者の直感に基づく仮説** であり、生産管理部からの確認されたペインではない。
→ MVP では過剰投資せず、Phase 2 のプロトタイプで実ユーザに当てて反応を見る。

### 未成熟イメージ
スポンサーが現時点で明確に言語化できない領域がある（「Something else」と回答）。
Phase 1 以降で仮説を提示しながら探る進め方となる。

詳細: `domain-context/persona/project-sponsor-persona.md`

## 4. 直近の目標地点

### MVP スコープ

**「商品マスタ登録 → 発注書作成（国内のみ）→ 発注書出力（Excel）」の3ステージを動く形で実装し、生産管理部が業務に使える状態にする**

### 対象機能
- ✅ 商品マスタ登録（2層構造、色×サイズ一括展開、マルチ仕入先単価）
- ✅ 発注書作成（国内画面: 発注先・納品先・倉庫1・取引先納入日 + 明細グリッド）
- ✅ 発注書出力（Excel、連絡文章テンプレート選択、発注番号採番）

### 対象外
- ❌ 海外発注フロー（4ロール、複数倉庫、週次出荷スケジュール 等）
- ❌ 見積・受注・出荷・在庫
- ❌ ワークフロー（承認なし）
- ❌ PDF 出力（将来）

### 拡張余地
データモデル設計時には海外フロー対応のための拡張余地（`customer`, `port_of_landing`, 複数倉庫, 複数日付 等）を NULL 許容で確保する。
