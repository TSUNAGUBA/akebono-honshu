## 1. パフォーマンス要件

### 1.1 画面・操作別の応答時間基準

| 操作カテゴリ | 対象機能 | 基準値 | 補足 |
|------------|---------|--------|------|
| **画面初期表示（一覧系）** | M-01, P-04, O-03 等の一覧画面 | **500ms 以下** | 95パーセンタイル。レビュー反映で 200ms → 500ms に緩和（JOIN/集計コスト現実化）|
| **画面初期表示（詳細・設定系）** | 詳細編集・マスタ単票・ログイン等 | **200ms 以下**（方法論デフォルト） | 95パーセンタイル |
| **検索結果表示** | M-01, P-04, O-03 | **100ms 以下**（方法論デフォルト） | 2万 SKU 規模での想定（§1.2 参照） |
| **マスタ単件保存** | M-02, M-03, M-04, M-05 | **300ms 以下** | コード重複・FK チェック含む |
| **商品マスタ保存** | P-01, P-05 | **500ms 以下** | 関連 SKU・単価レコード一括 INSERT/UPDATE |
| **サイズ展開（SKU 一括生成）** | P-02 | **500ms 以下**（50 SKU） | 100 SKU で 1秒以内 |
| **発注書保存** | O-01, O-02, O-04 | **500ms 以下** | 50明細想定 |
| **Excel 出力** | O-06 | **5秒以内** | 50明細、テンプレート流し込み。レビュー反映で 3秒 → 5秒に緩和（テンプレート処理・サーバ負荷余裕）|
| **画像アップロード** | P-06 | **5秒以内**（5MB 以下） | サムネ生成は非同期可。レビュー反映で 2秒 → 5秒に緩和（業務 LAN・サムネ生成考慮）|
| **画像表示（カードビュー初期）** | P-04 | **500ms 以下**（初期）+ 遅延読み込み | 一覧系扱い。スクロール時のサムネは遅延 OK |
| **ログイン認証** | C-01 | **500ms 以下** | パスワード検証含む |

### 1.2 データ量想定（5年運用想定）

> **レビュー反映:** 当初見積（企画 10,000 / SKU 100,000 / 発注 30,000 等）はオペレーター確認の結果「過大」と判定。実態に近い 1/5 規模（企画 2,000 / SKU 20,000 / 発注 5,000）を基準値として採用。Phase 7（リリース判定時）に生産管理部の実数値で再校正する。

| データ | 想定件数 | 影響 |
|--------|---------|------|
| 商品マスタ（product_family） | 〜2,000件（年間 400企画 × 5年） | 一覧検索パフォーマンスに影響 |
| 商品 SKU（product） | 〜20,000件（1企画 10 SKU 平均） | インデックス設計重要 |
| マルチ仕入先単価 | 〜100,000件（1 SKU 5仕入先平均） | JOIN コスト |
| 発注書 | 〜5,000件（年間 1,000 × 5年） | 一覧検索 |
| 発注明細 | 〜100,000件（1発注 20明細平均） | 詳細表示・集計 |
| 商品画像 | 〜10,000件（2,000企画 × 平均5枚） / 約 5GB | ストレージサイジング |
| 監査ログ | 〜400,000件（年間 80,000 × 5年） | 3年保管後はアーカイブ（SEC-16 参照） |
| ユーザマスタ | 〜100件 | 影響軽微 |

## 2. セキュリティ要件

### 2.1 通信・認証

| # | 要件 | 内容 |
|---|------|------|
| SEC-01 | 通信暗号化 | **HTTPS 必須**（HTTP は管理画面含め全廃） |
| SEC-02 | 認証方式 | MVP は ID/パスワード方式（SSO は Phase 4 で検討、Post-MVP の余地あり） |
| SEC-03 | パスワードポリシー | 8文字以上、英数字混在を必須。記号推奨。複雑度は AS-IS との互換性を Phase 4 で確認 |
| SEC-04 | パスワード保管 | ハッシュ化（bcrypt 等の業界標準アルゴリズム）。平文保管禁止 |
| SEC-05 | セッション管理 | **8時間タイムアウト**（業務時間相当）。明示的なログアウト機能 |
| SEC-06 | ブルートフォース対策 | 連続失敗 5回でアカウントロック（管理者解除）|
| SEC-07 | CSRF 対策 | フレームワーク標準機能を有効化 |
| SEC-08 | XSS 対策 | フレームワーク標準のテンプレートエスケープ + CSP 設定 |
| SEC-09 | SQL Injection 対策 | プリペアドステートメント / ORM 経由のみ DB アクセス |
| SEC-10 | ファイルアップロード | 画像 P-06: MIME 検証 + 拡張子検証 + ファイルサイズ上限（5MB）|

### 2.2 認可（権限制御）

| # | 要件 | 内容 |
|---|------|------|
| SEC-11 | **5**権限カテゴリ × レベル（2026-07-27 更新: 初版 4 + 勤怠）| C-02 機能要件参照。サーバサイドで全 API 呼び出しを検証。**品番台帳 / 発注書作成 / 勤怠は非単調エンコード**（`0=なし / 1=更新可能 / 2=参照のみ`）のため、書込判定は `>= 1` ではなく `== 1` で行うこと |
| SEC-12 | 削除済ユーザのアクセス | 削除フラグ ON のユーザはログイン不可（C-01 のエラー AUTH-003）|
| SEC-13 | クライアント側制御の補助扱い | UI 上のボタン非活性化はあくまで補助。最終判定はサーバ側 |

### 2.3 監査・ログ

| # | 要件 | 内容 |
|---|------|------|
| SEC-14 | 監査ログ記録（C-03） | 主要トランザクション（品番・発注・マスタ）のみ。who/when/what/before/after |
| SEC-15 | ログイン履歴 | 成功・失敗ともに記録（要 Phase 5 設計） |
| SEC-16 | 監査ログ保管期間 | **3年**（個人情報保護法の安全管理措置・社内統制目的として十分。電子帳簿保存法該当書類は別途、業務テーブル側で 7年保管）|
| SEC-17 | 監査ログの改竄防止 | 業務テーブルとは別の `audit_log` テーブル、INSERT のみ可（UPDATE/DELETE 不可な設計）|

### 2.4 その他

| # | 要件 | 内容 |
|---|------|------|
| SEC-18 | エラーメッセージの情報漏洩防止 | スタックトレース等の詳細情報はユーザに開示しない。エラーコードのみ |
| SEC-19 | 依存ライブラリの脆弱性 | CI/CD で脆弱性スキャン（Phase 4 で具体ツール選定） |

## 5. 可用性・運用

|------|------|

## 6. データ機密度（Phase 3 ゲート条件 3-4）

### 6.1 機密度判定

**総合機密度: 中（営業秘密含む）**

### 6.2 データ分類

| データ種別 | 機密度 | 根拠 | 対策レベル |
|-----------|--------|------|----------|
| **仕入単価**（product_supplier_price） | **中-高** | 取引先・仕入先との価格交渉情報、競争力源泉 | アクセス制限（5権限のうち品番台帳管理権限。2026-07-27 更新: 権限カテゴリは 4 → 5）+ 暗号化（保存時/通信時）+ 監査ログ |
| **商品マスタ**（11桁品番含む） | **中** | 商品設計・企画ノウハウ、季節・型式コード等の業務体系 | アクセス制限 + 監査ログ |
| **発注書履歴** | **中** | 取引先名・数量・価格の取引機密 | アクセス制限 + 監査ログ |
| **取引先・納品先情報**（delivery_destination） | **中** | 取引関係の機密、流通網情報 | アクセス制限 |
| **仕入先情報**（supplier） | **中** | 取引先関係、海外工場情報 | アクセス制限 |
| **ユーザマスタ** | **軽微（個人情報）** | 担当者名・部署のみ。住所/電話/個人番号は含まない | 認証保護、削除フラグ運用 |
| **連絡文章テンプレート** | **低** | 業務上の定型文 | 通常のアクセス制御 |
| **17マスタ（color, size 等）** | **低** | 体系的なコード参照データ | 通常のアクセス制御 |
| **商品画像** | **低-中** | 商品サンプル写真、企画段階情報 | アクセス制限 |
| **監査ログ** | **中** | 業務操作履歴、改竄防止が重要 | 改竄防止設計（SEC-17）|

### 6.3 規制・法令適用

| 規制 | 適用範囲 | 対応方針 |
|------|---------|---------|
| 個人情報保護法 | ユーザマスタの担当者名・部署 | 限定的データのため最低限の対応（業務委託契約レベル）。Phase 4 で詳細確認 |
| 不正競争防止法（営業秘密） | 仕入単価、取引先関係 | 営業秘密管理に該当。アクセス制御・監査ログ・契約上の秘密保持で対応 |
| 国際送金・税務（海外発注） | 海外フロー | **MVP 対象外**。Post-MVP で確認 |

### 6.4 対策レベル総括

| レベル | 該当データ | 主な対策 |
|--------|---------|---------|
| **高** | なし（MVP では該当なし） | – |
| **中-高** | 仕入単価 | アクセス制限 + 監査ログ + 通信/保存暗号化 |
| **中** | 商品マスタ、発注書、取引先、仕入先、監査ログ | アクセス制限 + 監査ログ |
| **軽微** | ユーザマスタ（担当者名のみ） | 認証保護 |
| **低** | テンプレート、マスタ参照、画像 | 通常の認証保護 |

## 7. 保守性・拡張性

| 項目 | 基準 |
|------|------|
| **コード品質** | 単体テストカバレッジ 70% 以上（バックエンドの主要ロジック） |
| **ログ品質** | アプリケーションログは構造化（JSON 等）、エラーレベル分類 |
| **エラーコード** | 全想定エラーにコード付与（AUTH-NNN, MASTER-NNN, PRODUCT-NNN, ORDER-NNN, EXPORT-NNN, IMAGE-NNN）|
| **設定値の外出し** | 環境変数 or 設定ファイル経由（接続文字列、シークレット等） |
| **将来の海外フロー拡張** | データモデルで `customer` `port_of_landing` 等を NULL 許容で確保（Phase 5 設計） |
