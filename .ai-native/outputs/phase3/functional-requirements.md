## 2. 機能カテゴリ別の入出力定義

### 2.1 横串（C-NN）

#### C-01: ログイン・セッション管理

| 観点 | 内容 |
|------|------|
| 入力 | ユーザID + パスワード |
| 処理 | ユーザマスタ参照、認証成功時にセッション開始 |
| 出力 | 認証成功 → ホーム画面 / 認証失敗 → エラー表示 |
| 業務ルール | 削除フラグ ON のユーザはログイン不可 |
| エラー | 想定エラーコード AUTH-001（ID 未登録）, AUTH-002（パスワード不一致）, AUTH-003（削除済ユーザ） |

#### C-02: 権限制御

| 観点 | 内容 |
|------|------|
| 入力 | セッション中のユーザID、操作対象（画面・機能ID） |
| 処理 | ユーザマスタの権限カテゴリを参照、レベルに応じて操作可否を判定 |
| 出力 | 許可 → 操作実行 / 拒否 → 403 相当の表示 |
| 業務ルール | 4権限カテゴリ（品番台帳:4レベル, 発注書作成:3レベル, 発注情報:2レベル, 工程実績:2レベル） |
| MVP UI 露出 | 工程実績管理権限は UI 非表示（DB のみ保持） |

#### C-03: 監査ログ記録

| 観点 | 内容 |
|------|------|
| 入力 | トランザクション種別（商品マスタ登録・改訂・削除 / 発注書登録・改訂・中止 / マスタ変更）、ユーザID、変更前後の値 |
| 処理 | `audit_log` テーブルに INSERT（非同期可、業務処理をブロックしない） |
| 出力 | 監査ログレコード（who, when, what, before/after の主要フィールド） |
| 業務ルール | 全画面変更ではなく、**主要トランザクションのみ**（参照は記録しない） |
| 性能 | 業務処理を 50ms 以上ブロックしない |

### 2.2 マスタ（M-NN）

#### M-01: マスタ一覧画面（18マスタ共通）

| 観点 | 内容 |
|------|------|
| 入力 | 対象マスタ種別、検索キーワード、論理削除フィルタ |
| 処理 | 対象マスタの一覧を取得、ソート・絞込 |
| 出力 | レコード一覧（コード, 名称, 主要属性, 削除フラグ） |
| 業務ルール | デフォルトは「論理削除フラグ OFF」のみ表示。OFF/ON 切替可 |
| 性能 | 初期表示 200ms、検索 100ms |

#### M-02: マスタ編集画面（18マスタ共通）

| 観点 | 内容 |
|------|------|
| 入力 | 新規 or 既存レコード ID、編集フィールド値 |
| 処理 | コード重複チェック、FK 整合性チェック、`updated_by`/`updated_at` 自動付与 |
| 出力 | 保存成功通知 / バリデーションエラー |
| 業務ルール | コード重複は即時エラー。FK 参照先削除済の場合は警告 |
| エラー | MASTER-001（コード重複）, MASTER-002（FK 不整合） |

#### M-03: ユーザマスタ管理（固有画面）

| 観点 | 内容 |
|------|------|
| 入力 | 社員番号, ユーザID, ユーザ名, 3権限レベル（品番台帳/発注書作成/発注情報）, 削除フラグ |
| 処理 | 社員番号の重複チェック、3権限カテゴリの整合性（無効な組み合わせはない） |
| 出力 | 保存成功通知 |
| 業務ルール | 担当属性（企画担当・営業担当）と工程実績管理権限は **DB 保持のみ、UI からは触らない**（後の機能拡張用、Post-MVP で UI 露出を検討）|
| MVP UI 露出フィールド（7件） | 社員番号, ユーザID, ユーザ名, 品番台帳管理権限, 発注書作成権限, 発注情報管理権限, 削除フラグ |
| DB 保持・UI 非表示フィールド（3件） | 企画担当, 営業担当, 工程実績管理権限 |

#### M-04: 仕入先マスタ管理（固有画面）

| 観点 | 内容 |
|------|------|
| 入力 | code, name, official_name, country_code, supplier_type, alert_target, item_conversion_code, ... |
| 処理 | `supplier_type` で工場/商社/原材料等を区別。`country_code` の FK 整合性 |
| 出力 | 保存成功通知 |
| 業務ルール | `supplier_type=工場` のレコードが11桁品番の7桁目候補となる |

#### M-05: 連絡文章テンプレート管理（3マスタ集約）

| 観点 | 内容 |
|------|------|
| 入力 | テンプレート種別（template_purchase / template_confirmation / text_purchase）、本文、standard_print_flag |
| 処理 | 種別ごとに保存 |
| 出力 | 一覧に反映 |
| 業務ルール | `standard_print_flag=true` のレコードは発注書出力時に自動プリポピュレート対象 |

### 2.3 商品（P-NN）

#### P-01: 商品マスタ新規登録画面

| 観点 | 内容 |
|------|------|
| 入力 | 商品タイプ, 季節, 機能, ブランド, 甲皮素材(material), 中底素材(material), 底素材(material), 商品分類, 商品名1, 商品名2 |
| 処理 | 各マスタ選択値から仮品番上位9桁を動的生成、`product_family` レコード作成準備 |
| 出力 | 仮品番プレビュー（11桁の上位9桁、4-6桁目は連番未確定） |
| 業務ルール | 全必須項目入力前は次ステップ（サイズ展開）に進めない |
| エラー | PRODUCT-001（必須項目未入力） |

#### P-02: サイズ展開機能

| 観点 | 内容 |
|------|------|
| 入力 | 選択された色リスト, 選択されたサイズリスト |
| 処理 | 色 × サイズの全組合せで 11桁 SKU を一括生成、連番（4-6桁目）を自動採番 |
| 出力 | グリッドに SKU 一覧表示 |
| 業務ルール | 同一企画内で SKU が重複しないこと |
| 仮品番衝突時の挙動 | **Phase 5 プロトタイプ検証で確定**（Phase 2 確定事項） |
| 性能 | 50 SKU 生成で 500ms 以内 |

#### P-03: マルチ仕入先単価入力

| 観点 | 内容 |
|------|------|
| 入力 | 各 SKU について (仕入先code, 仕入単価, 為替レート, 仕入単価決定日) を複数組 |
| 処理 | `product_supplier_price` テーブルに INSERT |
| 出力 | 一覧に反映 |
| 業務ルール | 1 SKU に対して同一仕入先の単価は最新のみ有効。履歴は別管理（Phase 3 で旧版保持と合わせて確定） |

#### P-04: 商品マスタ一覧・検索

| 観点 | 内容 |
|------|------|
| 入力 | フリーワード（品番・商品名）、絞り込み（企画年式、季節、商品タイプ、状態、削除フラグ）、ビュー切替（**表 / カード**）、ソート |
| 処理 | `product` テーブル + 関連マスタを JOIN し検索、選択中ビュー形式でレンダリング |
| 出力 | ヘッダ（タイトル + 件数 + 検索ボックス + ビュー切替トグル）+ 一覧本体 |
| 業務ルール | デフォルトビューは **カード**（参考: RMS 商品API 2.0 系の UX を踏襲）。ビュー選択はセッション中保持 |
| 遷移 | アイテム選択（カードクリック or テーブル行クリック）→ **P-05（商品マスタ詳細・修正）** へ遷移 |
| 性能 | 1万件オーダーで 100ms（初期表示）。ビュー切替は再フェッチ不要（クライアント側で再描画） |

##### P-04.a: カードビュー レイアウト

各カードに以下を表示:

| 要素 | 表示内容 |
|------|---------|
| ヒーロー画像エリア | 代表画像（先頭画像）+ **前/次ナビゲーションボタン**（カード内画像カルーセル）+ **インデクサ "N/M"** 表示 |
| サムネイル帯 | 副次画像のサムネ（2枚目以降、最大4枚）。横スクロール可 |
| 識別子 | 11桁品番 |
| タイトル | 商品名1 |
| サブテキスト | 商品名2 / 商品タイプ / 季節 等の要約 |
| 主要指標（3つ） | 仕入単価レンジ（min-max from product_supplier_price） / SKU バリエ数（色×サイズ） / 状態（新規/有効/削除済） |

**アクセシビリティ要件**（参照UXの DOM 構造より採用）:
- サムネ帯は `role="tablist"`、各サムネボタンは `role="tab"` + `aria-selected` でアクティブ状態を表現
- ナビゲーションボタンは `aria-label="前の画像"` / `aria-label="次の画像"`
- インデクサ ("N/M") は `aria-live="polite"` でスクリーンリーダー対応
- 全画像 `alt` 属性に商品名等を設定（空 alt は避ける）
- Tab/Shift+Tab/矢印キーでのキーボード操作対応

##### P-04.b: テーブルビュー レイアウト

列構成（フラット表示）:

| 列 | 内容 |
|----|------|
| 品番 | 11桁 SKU |
| 商品名 | 商品名1 |
| 商品タイプ | マスタ名 |
| 季節 | マスタ名 |
| 色 | 単一 or 複数 |
| サイズ | 単一 or 複数 |
| 仕入単価（min-max） | 数値レンジ |
| バリエ数 | SKU 件数 |
| 状態 | 新規 / 有効 / 削除済 |
| 最終更新者 | ユーザ名 |
| 最終更新日 | YYYY-MM-DD |

ソート: 任意列。デフォルトは最終更新日降順。

#### P-05: 商品マスタ詳細・修正

| 観点 | 内容 |
|------|------|
| 入力 | 対象 SKU の編集フィールド値、画像管理操作（P-06 連動） |
| 処理 | 更新、論理削除可、画像の追加/削除/並び替え |
| 出力 | 保存通知 |
| 業務ルール | 既に発注書に紐付いている SKU は削除不可（警告） |
| 遷移元 | P-04 のアイテム選択 |

#### P-06: 商品画像管理

| 観点 | 内容 |
|------|------|
| 入力 | 画像ファイル（複数選択可）、並び順、代表画像指定 |
| 処理 | アップロード → 保管（ストレージ方式は Phase 4 で決定）、サムネイル生成、メタデータ（ファイル名・サイズ・MIME・幅×高）保存 |
| 出力 | 画像 URL、サムネ URL、登録順 |
| 業務ルール | **1企画（product_family）あたり最大5枚**（OEM B2B 業務用途として妥当な枚数）。先頭画像が代表画像（カードビューのヒーロー）。形式: JPG/PNG/WebP、1枚あたり最大 5MB |
| エラー | IMAGE-001（容量超過）, IMAGE-002（形式不正）, IMAGE-003（保存失敗）, IMAGE-004（上限枚数超過） |
| 性能 | アップロード（5MB 以下）で 2秒以内、サムネ生成は非同期可 |
| ホスティング方式 | **Phase 4 で確定**。選択肢: (a) 内部オブジェクトストレージ（AWS S3 / GCS / Azure Blob）, (b) 外部 CDN（参照系の Rakuten 例: image.rakuten.co.jp 相当）, (c) サーバローカル＋静的配信 |

### 2.4 発注（O-NN）

#### O-01: 発注書作成（新規企画から）

| 観点 | 内容 |
|------|------|
| 入力 | P-01〜P-03 で確定した商品マスタ、発注先（supplier）, 納品先（delivery_destination）, 担当者一式（user × 9: 発注事業部+発注担当者+副1〜6+発注管理者）, 納入倉庫1, 取引先納入日 |
| 処理 | `purchase_order` ヘッダ + `purchase_order_line`（全 SKU 自動転記）を生成、作成管理番号採番 |
| 出力 | 発注書プレビュー、発注書出力画面へ遷移 |
| 業務ルール | 仕入単価は `product_supplier_price` から選択した仕入先に対応する単価を自動引当て |
| エラー | ORDER-001（必須項目未入力）, ORDER-002（仕入単価未設定の仕入先選択） |

#### O-02: 発注書作成（既存品番選択から）

| 観点 | 内容 |
|------|------|
| 入力 | P-04 から選択した既存 SKU 群, 各 SKU の発注数量, ヘッダ情報（O-01 と同じ） |
| 処理 | `purchase_order` + `purchase_order_line` 生成、作成管理番号採番 |
| 出力 | 同 O-01 |

#### O-03: 発注書一覧・検索

| 観点 | 内容 |
|------|------|
| 入力 | フリーワード（作成管理番号・発注番号・取引先名）、絞り込み（期間, 状態, 中止フラグ, 取引先, 仕入先）、ビュー切替（**表 / カード**）、ソート |
| 処理 | `purchase_order` を検索、選択中ビュー形式でレンダリング |
| 出力 | ヘッダ（タイトル + 件数 + 検索ボックス + ビュー切替トグル）+ 一覧本体 |
| 業務ルール | デフォルトビューは **テーブル**（発注業務は情報密度重視。P-04 とは逆のデフォルト） |
| 遷移 | アイテム選択 → **O-04（発注書修正・改訂）** へ遷移 |
| 性能 | 1万件オーダーで 100ms |

##### O-03.a: カードビュー レイアウト

| 要素 | 表示内容 |
|------|---------|
| ヘッダ帯 | 状態バッジ（新規/正式/中止）+ 発注番号 |
| タイトル | 取引先名 + 取引先納入日 |
| サブテキスト | 納品先 + 発注事業部 + 担当者 |
| 主要指標（3つ） | 明細品番数 / 仕入合計金額 / 中止フラグ |
| サムネ | 1明細目の品番に紐づく代表画像（P-06）。複数明細時は最大3枚のスタック表示 |

##### O-03.b: テーブルビュー レイアウト

| 列 | 内容 |
|----|------|
| 作成管理番号 | 例: 26-00411 |
| 発注番号 | 例: S3858（出力後） |
| 取引先 | 名称 |
| 納品先 | 名称 |
| 発注先（仕入先） | 名称 |
| 取引先納入日 | YYYY-MM-DD |
| 明細品番数 | 数値 |
| 状態 | 新規/正式/中止 |
| 最終更新者 | ユーザ名 |
| 最終更新日 | YYYY-MM-DD |

ソート: 任意列、デフォルトは最終更新日降順。

#### O-04: 発注書修正・改訂

| 観点 | 内容 |
|------|------|
| 入力 | 対象発注書 ID, 編集フィールド値 |
| 処理 | 修正内容を反映、**枝番採番**（既存発注番号 `Snnnn` → `Snnnn-01` 等） |
| 出力 | 改訂版発注書、再出力導線へ |
| 業務ルール | 旧版データの物理保持は **Phase 3 で確定** |
| エラー | ORDER-003（中止済発注書の改訂不可） |

#### O-05: 発注中止

| 観点 | 内容 |
|------|------|
| 入力 | 対象発注書 ID |
| 処理 | `is_cancelled = true` を立てる。物理削除しない |
| 出力 | 中止確定通知 |
| 業務ルール | 中止発注書は履歴として残る。再開（中止解除）の可否は要確認 |

#### O-06: 発注書 Excel 出力

| 観点 | 内容 |
|------|------|
| 入力 | 対象発注書 ID |
| 処理 | Excel テンプレートに発注書データを流し込み、初回出力時に**発注番号採番**（S 始まり） |
| 出力 | Excel ファイル（ダウンロード）、発注番号確定 |
| 業務ルール | **MVP は発注書のみ**。管理表帳票は Post-MVP（既存システムの「出力帳票選択」3択 UI も MVP では作らない） |
| 性能 | 1発注書（50明細）で 3秒以内 |
| エラー | EXPORT-001（テンプレート不正）, EXPORT-002（ファイル生成失敗） |

#### O-07: 連絡文章選択

| 観点 | 内容 |
|------|------|
| 入力 | 対象発注書 ID, 連絡文章テンプレート選択 |
| 処理 | `document_text_purchase` から複写 or 自由編集、最大6行 |
| 出力 | 発注書本文への反映 |
| 業務ルール | 「標準印字取込」ボタンで `standard_print_flag=true` のテンプレートを一括投入 |

## 4. ユーザー権限（4権限カテゴリ × レベル）

### 4.1 権限カテゴリと操作レベル

| 権限カテゴリ | レベル | MVP UI | 機能適用範囲 |
|-------------|--------|--------|------------|
| 品番台帳管理権限 | なし / 更新可能 / 参照のみ / 参照のみ(制限) | ✅ 露出 | P-01〜P-05 |
| 発注書作成権限 | なし / 更新可能 / 参照のみ | ✅ 露出 | O-01〜O-07 |
| 発注情報管理権限 | なし / あり | ✅ 露出 | （要確認: 発注情報の参照系画面で使用想定） |
| 工程実績管理権限 | なし / あり | ❌ UI 非表示 | **MVP 対象外**（DB のみ保持） |

### 4.2 担当属性（MVP では UI 非表示）

| 属性 | MVP UI | 用途 |
|------|--------|------|
| 企画担当 | ❌ UI 非表示 | DB 保持のみ。MVP では商品マスタ登録時の「企画者」として使わない。Post-MVP で活用検討 |
| 営業担当 | ❌ UI 非表示 | DB 保持のみ。MVP では使用なし。Post-MVP で活用検討 |

**方針:** 担当属性2件 + 工程実績管理権限の計3フィールドは、既存システムとのスキーマ互換性のため DB には保持するが、MVP では UI から触らない（M-03 仕様参照）。

### 4.3 マスタ管理者ロール

`M-NN` 全機能の更新権は、**特権ユーザ（例: `owner`）または特定の権限組合せ** に限定する想定。Phase 4 でアクセス制御方式を確定。
